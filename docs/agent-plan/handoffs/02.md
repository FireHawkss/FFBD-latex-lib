## Result

`tikzffbd-model.lua` exports `new({environment_id=string, options?=table})`
and `inspect(spec) -> mutable deep copy`. The builder returned by `new` has:

```text
add_function({id, text_ref, number?}) -> id
add_start({id, text_ref, number?}) -> id
add_finish({id, text_ref, number?}) -> id
add_flow({source, target, condition_ref?}) -> flow ID
add_feedback({source, target, condition_ref?, preferred_feedback_side?}) -> flow ID
add_branch({source_id, logic?=and, arms={target | {target, condition_ref}, ...}}) -> connector ID
add_join({arms={source, ...}, target_id, logic?=and}) -> connector ID
add_structure({id, member_ids, input_member_ids?, output_member_ids?, type_ref?, info_ref?, style?=shaded}) -> id
add_annotation({id, owner_id, type_ref, body_ref, preferred_position?, position_strength?}) -> id
seal() -> immutable Spec | nil, immutable Diagnostic[]
```

Each builder call takes the next positive declaration index. IDs are
`@branch/<index>`, `@join/<index>`, and `@flow/<index>/<ordinal>`; ordinals
follow expansion order (branch source flow first, then user ordered arms;
join user ordered arms first, then target flow). They do not depend on geometry.
The Spec keeps declaration and arm order, conditional text references,
structure member and boundary member order, and a `source` or
`source_command` record with command and index. Options default to
`direction=right`, `scale=1`, `multipage=false`. No raw TeX label content is
accepted; callers pass `@text/...` references.

`seal` checks user IDs across nodes, structures, and annotations; node and
flow references; AND/OR logic; branch/join arm counts and connector incidence;
member uniqueness and ownership; boundary port membership; annotation
positions; option values; and cycles among forward flows. Feedback flows are
retained without participating in the forward DAG. The resulting Spec and
diagnostics are recursively immutable; `inspect` supplies a copy for tracing.

## Known limits and risks

The model does not infer which split matches a join. An ambiguous or
nested-looking graph remains representable for part 05. Text references are
validated syntactically; the TeX bridge in part 03 must ensure they resolve to
registered tokens. The legacy `.sty` is not connected to this builder yet.
