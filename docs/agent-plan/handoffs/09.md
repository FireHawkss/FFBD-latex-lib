## Result

`tikzffbd-solver.lua` exports `solve(Spec, Metrics, Frame) -> Scene | nil, Diagnostic[]` and `SEARCH_BUDGET = 64`. It normalizes constraints, obtains up to eight row/page plans, places each, enumerates measured note positions in fixed order, routes with those notes as obstacles, places measured flow conditions against routed segments, and compares valid complete Scenes lexicographically. At most 64 complete note/route combinations are evaluated across all plans. The solver returns the best valid Scene with a warning if the budget is reached; if none is valid, it returns a specific conflict or a budget diagnostic with the last conflict code. It preserves the user's scale and rejects hard multipage overflow.

`tikzffbd-annotations.lua` exports `positions`, `note_candidates`, `labels`, `page_of`, `overlap`, and `hits_path`. Eight note positions use measured boxes, avoid node and note boxes, and require containment within a measured owner group. Explicit hard positions constrain enumeration; soft positions can move. Flow labels use measured `condition_ref` boxes next to their semantic path and avoid blocks, notes, prior labels, and other paths. `tikzffbd-quality.lua` exports `vector` and `less`.

The seven score components, in contract order, are: `0` for hard feasibility; wrong-way distance in sp; route crossing count plus congestion count; strong constraint cost plus placement crossing count; placement gap variance in sp² plus blank bounding area plus between-page bounding-area variance plus weak constraint cost; route length in sp plus bends weighted by measured route gap; and the count of notes moved from preferred positions. Comparison is strictly lexicographic with deterministic declaration-order ties. These are provisional numeric weights; rendered visual calibration is still required.

`Scene.pages` includes actual node and structure rectangles, selected notes, page-specific path legs, flow labels, measured reciprocal continuation marker boxes, and complete bounding rectangles. The checked-in single-page and multipage JSON fixtures validate against the version 1 Scene contract and can be consumed by part 10.

## Known limits and risks

- Note search keeps at most 64 partial placements in declaration order. It may miss a feasible or better combination when many notes interact; the budget warning reports truncation.
- A note owned by a node inside a structure must fit the measured group rectangle. If no such position exists, the solver diagnoses instead of expanding the group. Reproduce with a tightly padded group and a large measured note.
- Score weights have automated priority tests but no visual calibration. The available `.sty` still draws the prototype, so these Scenes cannot yet be visually rated as successor output.
- Continuation text must be measured and present in `Metrics.by_text_ref` under the planner's generated reference; otherwise the solver returns `unmeasured-continuation`.
