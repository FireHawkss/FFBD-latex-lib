## Result

`tikzffbd-constraints.lua` exports `normalize(spec, frame) -> Constraint[] | nil, Diagnostic[]`
and `check(candidate, constraints) -> Diagnostic[], {strong=number, weak=number}`.
The first return from `normalize` is a deterministic array in option, explicit
constraint, annotation, page-fit order. It defaults `max-columns` to five and
its strength to hard; it maps `soft` to strong. It normalizes plain and soft
`row-break` records, `keep-together` with `row|page`, explicit annotation
positions, the environment annotation side as weak, and multipage page fit as
hard. All records use the same strength and diagnostic mechanism. Future
options can add records with these strengths without a new evaluator API.

`candidate` may contain `{plan, scene, spec, frame, complete}`. Missing phase
data defers the corresponding check, supporting partial plans. Plan rows use
`ordered_node_ids` as column slots. A completed Scene supplies page bounds and
annotation positions. Hard violations are errors; strong/weak violations are
warnings with one cost per violated row, group, or annotation. The evaluator
does not choose geometry or change candidate data. The TeX bridge now exposes
`tikzffbd_bridge.last.Constraints` and diagnostic errors after `finish`.
`model.Builder:add_constraint(record)` permits a future input layer to add
group keeping or other high-level constraints before sealing.

Diagnostic codes: `environment-mismatch`, `invalid-frame`, `invalid-option`,
`invalid-constraint`, `unknown-constraint-target`, `hard-conflict`,
`max-columns-exceeded`, `row-break-violated`, `row-break-unresolved`,
`keep-together-violated`, `annotation-position-violated`,
`annotation-unresolved`, and `page-fit-violated`. Every record includes source
command and declaration index, affected IDs, constraint IDs, and suggested
actions. A hard group containing `b,c,d` with `\endrow` after `b` reports
`hard-conflict` naming both the keep and row-break IDs. A soft five-column
limit on a six-slot row reports `max-columns-exceeded` with strong cost 1.

## Known limits and risks

There is no successor planner yet. The evaluator rejects or scores proposed
rows and Scenes but cannot establish that a solver always returns a feasible
candidate. It checks constraint-specific feasibility; block overlap, route
clearance, structure containment, and label clearance require later geometry,
routing, and quality phases. Group keeping has no public TeX option yet; the
builder method is available to that future input path. The current legacy
drawing pass does not use the normalized constraint set.
