## Result

The new tikzffbd-routing.lua exports route(Geometry, Spec, occupied_annotations)
returning Routes or nil plus Diagnostic. It reads measured rectangles, row signs,
provisional ports, structure boundaries, page extents, and continuation records.
It does not move nodes or create TikZ commands. Port IDs are stable and derived
from semantic flow IDs.

Each same-page flow has source and target ports, ordered integer-sp orthogonal
points, and a page index. A cross-page flow has ordered page_segments linked by
the planner's reciprocal continuation marker IDs. Main path fields mirror its
first page segment for the version 1 Routes schema; additive semantic source
and target port IDs identify the true endpoints. A group crossing records
boundary_port_ids and uses only declared input/output members. Multiple nested
boundaries at one endpoint return a candidate conflict.

The router tries direct Manhattan bends, then searches a sparse local
visibility graph of obstacle corners, endpoint projections, and adjacent
corner projections. Costs account for length, bends, wrong-way travel, and
crossings. A crossing flow gets one bounded rip-up/re-route attempt. Collinear
overlap between related flows is recorded in shared_trunks with both owners;
unrelated overlap is recorded in congestion. Feedback flows reserve an outer
lane when clear. Routes.costs records length, bends, crossings, wrong-way
distance, work used/budget, exhaustion, and rip-up count. The global budget is
120,000 visibility checks/search states per call; a searched corridor is capped
at 3,000 vertices.

Conflicts include environment-mismatch, missing-port-candidate,
undeclared-structure-crossing, missing-structure-boundary,
nested-structure-corridor, invalid-structure-port,
page-continuation-unresolved, obstructed-corridor,
obstructed-continuation, visibility-vertex-budget,
route-work-budget, route-through-obstacle, and
nonorthogonal-boundary/nonorthogonal-continuation. Diagnostics name the flow
and obstructed region or corridor for candidate selection.

## Known limits and risks

The visibility graph is heuristic and bounded; a feasible corridor may still
return obstructed-corridor or a budget conflict, requiring another structural
candidate. Nested group crossings at one endpoint diagnose rather than route.
Continuation marker points are provisional and have no measured label boxes
yet; part 09 must place those boxes and recheck page bounds. Cross-page route
legs and group ports are geometric data, but no successor renderer consumes
them yet. Visual readability remains unreviewed until parts 09–11 produce
solved Scenes and PDFs.
